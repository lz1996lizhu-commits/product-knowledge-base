# 如何根据录用申请单据字段动态切换定薪方式

## 问题描述

标准产品的定薪方式通过全局参数统一配置（人才供应云 > 招聘基础服务 > 参数配置 > 招聘服务直通车参数配置 > 录用参数配置），只能选择"招聘定薪"或"薪酬定薪"二选一。企业希望根据录用申请单据上的字段（如"拟入职序列"）动态切换定薪方式，需通过二次开发实现。

## 定开方案

### 场景一：新增录用申请单（界面初始化）

增加**表单插件**，在 `afterCreateNewData` 事件中根据自定义规则设置定薪方式：

```java
// 表单插件 - afterCreateNewData 事件
// salaryparam 字段：0 = 招聘定薪，1 = 薪酬定薪
this.getModel().setValue("salaryparam", val);
```

**实现要点：**

- 在 `afterCreateNewData` 事件中获取单据相关字段值（如拟入职序列），根据自定义业务规则判断 val 取值
- val = 0 对应招聘定薪，val = 1 对应薪酬定薪
- 该逻辑在新增单据初始化时自动执行，用户打开新增页面即根据规则预设定薪方式

### 场景二：修改录用申请单（字段变更联动）

在 `propertyChanged` 事件中监听关键字段（如"职位序列"）的变化，动态切换定薪方式：

```java
// 表单插件 - propertyChanged 事件
// 监听职位序列等字段变化，根据自定义规则重新设置定薪方式
this.getModel().setValue("salaryparam", val);
// 设置完成后需局部刷新界面
```

**实现要点：**

- 在 `propertyChanged` 中判断触发字段是否为"职位序列"等业务字段
- 根据新值重新计算定薪方式，调用 `setValue("salaryparam", val)` 设置
- 设置完成后需**局部刷新界面**，确保定薪相关区域按新方式显示
- **已保存定薪数据的清理**：切换定薪方式后，若之前已保存了旧定薪方式的数据，二开需评估是否在 `propertyChanged` 中一并清理旧数据，避免数据不一致

### 注意事项

1. `salaryparam` 字段值含义：0 = 招聘定薪，1 = 薪酬定薪
2. 切换定薪方式后务必局部刷新界面，否则界面展示可能与实际定薪方式不匹配
3. 对于已有定薪数据的场景，需评估是否需要联动清理，防止出现"薪酬定薪方式下残留招聘定薪数据"的情况
4. 建议在清理逻辑中增加用户确认提示，避免误清重要数据
