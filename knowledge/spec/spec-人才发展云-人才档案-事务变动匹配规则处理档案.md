用例总数: 54

## 用例 7884: 员工入职，协作应用配置匹配成功，自动生成人才档案成功

**功能路径**: 人才发展云（pro）-人才档案-事务变动匹配规则处理档案-入职

**功能说明**: 
1、用户有人才档案和员工变动及处理的操作权限
2、员工 +  任职经历id在人才档案列表无数据
3、员工任职经历.行政组织查询员工管理关系策略获取人才BU在协作应用配置列表已配置数据，且协作处理策略为自动处理

**步骤描述**: 
1、核心人力云-入职管理发起入职并确认入职成功，检查是否自动生成人才档案
2、检查人才档案的人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段值是否与协作应用配置下的协作规则方案一致
3、检查员工变动处理列表
4、检查HR基础服务云-HR基础服务-HR许可员工明细，是否占用人才发展应用分组许可

**预期结果**: 
1.1、自动生成人才档案成功，人才档案列表新增一条人才档案数据
结束日期晚于或等于当前系统时间，管理关系状态 = 生效；
结束日期早于当前系统时间，管理关系状态 = 失效

人才档案详情-个人基本信息页签下：
1.2、组织分配附表：服务年限、职级职等、任职经历附表正确记录当前组织分配下数据，同人员档案一致
1.3、员工附表：基本信息、教育经历、前工作经历、项目经历、培训经历、职业资格、执业资格、职称信息、专业技能、语言能力、专利发明、奖惩记录附表正确记录当前员工的数据，同人员档案一致
2、人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段值与协作规则方案的值一致
3、列表新增一条变动大类 = 入职，变动处理状态 = 已处理 的变动信息
4.1、若该员工对应的全球员工已存在管理关系状态 = 生效 的人才档案，则不会重复占用许可
4.2、若该员工对应的全球员工不存在管理关系状态 = 生效 的人才档案，则许可占用数+1

1、不会自动生成人才档案

3、变动处理状态由待确认变更为：已处理
4.1、自动生成人才档案成功，人才档案列表新增一条人才档案数据

5、人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段值与协作规则方案的值一致
6.1、若该员工对应的全球员工已存在管理关系状态 = 生效 的人才档案，则不会重复占用许可
6.2、若该员工对应的全球员工不存在管理关系状态 = 生效 的人才档案，则许可占用数+1

4.3、员工附表：基本信息、教育经历、前工作经历、项目经历、培训经历、职业资格、执业资格、职称信息、专业技能、语言能力、专利发明、奖惩记录附表正确记录当前员工的数据，同人员档案一致
5、人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段值与协作规则方案的值一致
6.1、若该员工对应的全球员工已存在管理关系状态 = 生效 的人才档案，则不会重复占用许可
6.2、若该员工对应的全球员工不存在管理关系状态 = 生效 的人才档案，则许可占用数+1

## 用例 7887: 员工入职，协作应用配置匹配成功，手动更新人才档案成功

**功能路径**: 人才发展云（pro）-人才档案-事务变动匹配规则处理档案-入职

**功能说明**: 
1、用户有人才档案和员工变动及处理的操作权限
2、员工 +  任职经历id在人才档案列表有数据 且 管理关系状态 = 生效
3、员工任职经历.行政组织查询员工管理关系策略获取人才BU在协作应用配置列表已配置数据，且协作处理策略为手动处理
4、协作应用配置关联的协作规则方案：人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段可通过配置规则或设置默认值，与入职事务变动默认赋值不同

**步骤描述**: 
1、核心人力云-入职管理发起入职并确认入职成功，并手动在人才档案列表通过批量创建功能生成人才档案
2、进入员工变动处理列表，对步骤1入职生成的变动数据操作确认生效
3、检查人才档案列表和档案详情
4、检查HR基础服务云-HR基础服务-HR许可员工明细，是否占用人才发展应用分组许可

**预期结果**: 
1、生成人才档案成功
2、变动处理状态由待确认变更为：已处理
3、列表和档案详情页的人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段已更新，与协作规则方案一致
4、许可余额不变，更新档案不会重复占用许可

**功能路径**: 人才发展云（pro）-人才档案-事务变动匹配规则处理档案-调动-跨公司调动

**功能说明**: 
1、用户有人才档案和员工变动及处理的操作权限
2、员工任职经历.行政组织查询员工管理关系策略获取人才BU在协作应用配置列表未配置数据
3、员工 +  原任职经历id在人才档案列表有数据且管理关系状态 = 生效
4、员工 +  目标任职经历id在人才档案列表有数据但管理关系状态 = 失效

**步骤描述**: 
1、核心人力云-调配管理-调动管理发起调动申请并确认到岗，并手动在人才档案列表通过批量生效功能对目标任职经历生成人才档案
2、对步骤1生成的人才档案通过批量失效功能，失效人才档案
3、进入员工变动处理列表，检查调动生成的变动数据 - 变动后人才档案信息的字段值
4、变动数据详情页手动填写变动后人才档案信息字段后，点击确认生效
5、检查目标任职和原任职人才档案列表和档案详情

**预期结果**: 
1、生成人才档案成功
2、人才档案失效成功
3、变动后人才档案信息字段：人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段均为空
4.1、确认生效成功
4.2、变动处理状态由待确认变更为：已处理
5、列表和档案详情页的人才管理组织、管理部门、人才档案分组、开始日期、结束日期字段已更新，与手动填写变动后人才档案信息字段值一致
