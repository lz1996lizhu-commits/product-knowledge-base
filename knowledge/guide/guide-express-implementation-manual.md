# 招聘服务直通车从0到1实施配置手册

> 来源：https://vip.kingdee.com/knowledge/877612316425458176
> 更新日期：2026-08-18

**适用产品**：金蝶 AIHR · 人才供应云 — 招聘服务直通车

**适用读者**：系统实施顾问、交付顾问、客户方关键用户（招聘模块管理员、IT集成负责人）

**手册定位**：本手册以系统实施顾问视角，给出从项目启动到上线验证、从零搭建招聘服务直通车业务的端到端配置指引，涵盖实施准备、系统参数、基础配置、第三方招聘系统集成、录用与入职协同业务要点、工作流与权限、定时任务与上线验证全过程。

# 1 业务全景与实施蓝图

## 1.1 产品定位

招聘服务直通车是人才供应云面向**高信息安全要求企业**提供的招聘领域**混合云一体化**解决方案，重点解决第三方招聘系统与金蝶 AIHR 核心人力入职业务的无缝衔接。内部招聘全流程由金蝶 AIHR 原生提供，外部招聘则通过直通车集成生态伙伴招聘系统，实现从候选人获取到入职办理的完整录用闭环。

直通车的核心安全价值在于：敏感数据（录用通知书、录用定薪信息、行政组织）在金蝶 AIHR 内**闭环管理**——录用定薪数据由薪酬系统独立管理（业务隔离）、本地加密存储，保护企业信息与组织信息安全。

系统路径为：**人才供应云 > 招聘服务直通车**。

## 1.2 与相关模块的关系

| 模块 | 关系说明 |
|------|----------|
| 招聘基础服务 | 直通车的公共底座：基础资料、招聘渠道、消息模板、参数配置（含直通车参数配置）由其统一管理 |
| 内部招聘 | 平行模块，负责企业内部招聘全流程；直通车负责外部招聘（社会招聘）集成场景 |
| HR 基础服务 | 提供人员/组织/编制主数据、职位体系、登录管理（候选人登录页）、拟入职人员信息、黑名单管理等 |
| 核心人力 | 录用闭环的落点：入职管理（待启动入职、入职办理）、调动协同、员工档案；入职/转正/离职状态回传招聘端 |
| 薪酬管理 | 招聘定薪协同：选择"薪酬定薪"方式时，定薪数据下推薪酬与入职模块；录用定薪数据由薪酬系统独立管理 |
| 集成服务云 / 开放服务云 | 外部系统集成的技术底座：集成方案部署、连接配置、服务流程、OpenAPI 与第三方应用注册 |

## 1.3 端到端业务流程

直通车主链路包含八个环节：

| 序号 | 环节 | 负责人 | 关键动作 |
|------|------|--------|----------|
| 1 | 获取候选人信息 | 招聘专员 | 从第三方招聘系统获取拟录用候选人信息 |
| 2 | 录用申请 | 招聘专员 | 基于候选人信息发起录用申请，填写拟入职信息；按定薪方式同步启动定薪业务 |
| 3 | 定薪 | 薪酬专员 | 完成候选人定薪；定薪项目可一键引用嵌入录用通知书 |
| 4 | 录用审批 | 用人部门经理 / 招聘专员 | 按人群自动匹配录用审批流程；审批人可见内容由参数控制；支持撤回、废弃 |
| 5 | 录用通知书发送 | 招聘专员 | 多模板管理；引用定薪项目变量自动填充；支持加密 PDF，经邮件/短信推送 |
| 6 | 候选人回复 | 候选人 | 手机/邮箱安全验证后在线查看并回复；支持 HR 代回复；链接有效期管控 |
| 7 | 发起入职 | 招聘专员 | 候选人接受录用后发起入职协同，审批通过后发起入职，数据传递至入职模块 |
| 8 | 入职办理 | HRSSC / 候选人 | 候选人申请入职、HRSSC 办理入职；入职结果（确认入职/终止入职/转正/离职）回传第三方招聘系统，形成闭环 |

两种实施模式可在项目中按客户场景选择：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 完整流程 | 录用申请 + 录用通知书发放 + 入职协同的完整链路 | 标准社会招聘场景 |
| 轻量化流程 | 无需录用申请/录用通知，候选人通过考核后直接发起入职协同 | 灵活用工、门店快速招聘 |

## 1.4 实施蓝图（推荐步骤）

建议按以下顺序推进实施：

1. **招聘业务管控**：配置人才供应的人才招聘管控视图及关系管理策略，明确招聘管理组织与行政组织的管控关系。
2. **招聘人员权限**：完成角色配置与权限档案配置，为招聘专员、薪酬专员、用人部门经理、HRSSC 等角色分配功能权限与数据权限。
3. **系统参数配置**：完成招聘服务直通车参数配置（简历解析、定薪方式、审批可见内容、通知书有效期与附件加密等，见第3章）。
4. **基础配置**：按依赖顺序配置招聘渠道、消息模板、录用通知书模板，并核对候选人录用登录页与隐私声明配置（见第4章）。
5. **第三方招聘系统集成**：如需对接外部招聘系统，按第5章文档完成生态连接与集成配置。
6. **工作流配置**：引用预置工作流模板，为录用申请单、录用通知单、入职协同申请单配置审批工作流或免审批规则（见第7章）。
7. **上线验证**：按实施验证清单执行端到端演练（候选人同步 → 录用 → Offer → 回复 → 入职协同 → 入职 → 状态回传），输出验收记录（见第10章）。

## 1.5 角色与职责

| 角色 | 主要职责 |
|------|----------|
| 招聘专员 | 获取/维护候选人，发起录用申请、录用通知与入职协同，代候选人回复，管理应聘全程 |
| 薪酬专员 | 完成候选人定薪（薪酬定薪方式下），维护定薪项目 |
| 用人部门经理 | 录用审批决策，查看简历、面试评价等授权可见信息 |
| HRSSC | 办理入职手续，处理入职流程 |
| 候选人 | 接收录用通知书，安全验证后在线查看与回复 |
| IT 管理员 | 集成方案部署、连接配置、OpenAPI 注册与联调 |

# 2 实施前置条件

## 2.1 模块与部署准备

实施直通车前需确认以下模块/能力已部署或规划到位：

| 依赖项 | 说明 |
|--------|------|
| 人才供应云（招聘基础服务） | 提供参数配置、业务配置（渠道/模板）底座，必须启用 |
| 核心人力（入职管理） | 提供待启动入职、入职办理、变动操作等基础资料，入职闭环的落点，必须启用 |
| HR 基础服务 | 提供行政组织、拟入职人员信息、登录管理（候选人登录页配置）等，必须启用 |
| 薪酬管理 | 仅当定薪方式选择"薪酬定薪"时需要，**需提前订阅并部署薪酬功能** |
| 集成服务云 | 集成方案部署与连接配置底座，对接第三方招聘系统时必须 |
| 开放服务云（OpenAPI） | 第三方应用注册、API 授权与接口调试，对接第三方招聘系统时必须 |
| AI 大模型（平台文档提取能力） | 仅当启用"简历解析AI"参数时需要，**需提前订阅并部署 AI 大模型** |

## 2.2 网络环境

与第三方招聘系统对接时，需确认第三方系统与金蝶系统网络环境互通、应用部署服务器与文件服务器网络通畅。

## 2.3 组织与主数据

实施前需完成以下主数据梳理：

1. **招聘管理组织**：明确企业招聘业务的组织维度，作为参数作用域与数据权限的判定基础。
2. **行政组织**：完成行政组织维护，作为拟入职部门等引用的基础。
3. **职位体系**：岗位、职位、职等/职级方案，录用申请拟入职信息将引用。

## 2.4 权限规划

直通车的功能权限按对象细分，实施时需按角色逐一分配：

| 权限类别 | 典型权限项 |
|----------|------------|
| 候选人列表功能权限 | 候选人查询/新增/修改/删除、结束应聘、恢复应聘、修改管理人、简历解析 |
| 单据功能权限 | 新增/删除录用申请、新增/删除录用通知、新增/删除入职协同申请 |
| 单据操作权限 | 修改/保存、提交、提交并生效（免审批）、撤销、废弃、删除；录用通知单另有发送、回复权限 |
| 热区跳转查询权限 | 录用申请单、录用通知单、入职协同申请单、招聘职位的查询权限（分别控制工作台与列表热区点击） |
| 数据权限 | 按招聘管理组织维度的数据规则权限（修改/提交/提交并生效/发送/回复/查看候选人） |
| 配置类权限 | 参数配置查询/操作、生态租户维护、候选人同步日志、消息模板与录用通知书模板维护、招聘渠道维护 |
| 薪酬协同权限 | "新增候选人定薪单"功能权限（薪酬定薪方式下校验）、定薪查询权限 |

提示：无参数配置查询权限时参数菜单不显示；无"简历解析"权限时候选人详情标准简历页签及批量新增弹窗的解析按钮不可用；无定薪查询权限时薪酬信息显示"无权限查看"。

## 2.5 出厂预置数据核对

系统出厂已预置部分数据，实施时应先核对再决定新建或修改：

| 预置范围 | 预置内容 |
|----------|----------|
| 招聘服务直通车参数 | 录用通知书有效期、附件加密等参数默认值 |
| 录用通知书 | 预置模板及变量配置 |
| 定薪方式相关 | 招聘原因、面试方式、面试类别 |
| HR 基础服务 | 候选人录用登录页（编码 can_offer）、隐私声明关联 |
| 安全管理 | 招聘服务直通车隐私政策隐私声明（编码 tsrsc_1010_S，业务对象=录用通知书） |
| 消息模板 | 内部招聘/社会招聘预置通知模板（与预置文档一致） |
| 工作流服务 | 录用申请/录用通知/入职协同单三个预置审批流程模板（见第7章） |
| 系统服务 | 国家/地区、行政区划、打印模板、隐私中心 |

# 3 系统参数配置

## 3.1 配置路径与作用域

配置路径：**人才供应云 > 招聘基础服务 > 参数配置 > 招聘服务直通车参数配置**。

参数作用域按**招聘管理组织**生效（F7 选择用户权限内组织），界面提示"仅对所选招聘管理组织生效"。如需同步下级组织、参数复制或集团管控，需到**基础服务云 > 公共设置 > 参数配置 > 系统参数**另行配置。

## 3.2 候选人参数配置

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| 简历解析AI | 开启后，单个及批量新增候选人时，上传的原始简历附件经大模型解析，内容自动填充到标准简历表单 | 开启 / 关闭 | 关闭 |

**实施要点**：该参数依赖平台文档提取能力，开启前必须确认 AI 大模型已订阅并部署，否则开启后无法解析。

## 3.3 录用参数配置

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| 定薪方式 | 录用流程中的定薪规则 | 招聘定薪 / 薪酬定薪 | 以现场确认为准 |
| 录用审批可见内容 | 录用审批时审批人可见的候选人信息 | 多选：简历、考试测评、面试评价、附加资料 | 默认全部勾选 |
| 录用通知审批可见内容 | 录用通知审批时审批人可见内容 | 多选：简历、考试测评、面试评价、附加资料 | 默认全部勾选 |
| 录用通知书有效期（天） | 据此推算录用通知书默认失效时间 | 整数 1~366，或选择"不限"（选择后输入框清空） | 30 |
| 录用通知书附件加密 | 开启后通知中插入的录用通知书附件加密，须验证密码才能查看 | 开启 / 关闭 | 关闭 |

**定薪方式选择指引**：

| 方式 | 说明 | 前置条件 |
|------|------|----------|
| 招聘定薪 | 在录用申请单上仅录入薪酬常见字段（基本工资、绩效奖金等），字段数据库加密存储 | 无额外订阅要求 |
| 薪酬定薪 | 使用薪酬功能与定薪结构，定薪数据下推至薪酬和入职模块；录用申请单隐藏招聘定薪字段、显示薪酬定薪区域 | 需提前订阅并部署薪酬功能；需为薪酬专员分配"新增候选人定薪单"功能权限 |

提示：定薪方式为全局参数二选一。若客户需要按单据字段（如不同职位序列）动态切换定薪方式，属于二开场景，需通过表单插件实现，实施时应提前评估并在方案阶段确认。

## 3.4 入职协同参数配置

| 参数 | 说明 | 可选值 | 默认值 |
|------|------|--------|--------|
| 入职协同审批可见内容 | 入职协同审批时审批人可查看的候选人信息 | 多选：简历、考试测评、面试评价、附加资料 | 默认全部勾选 |

# 4 基础配置

## 4.1 招聘业务管控（前置）

实施第一步为招聘业务管控：配置人才供应的**人才招聘管控视图**及**关系管理策略**，确立招聘管理组织与行政组织之间的管控关系。该配置决定后续参数作用域、数据权限判定与生态租户组织映射的基础，必须在业务配置之前完成。

## 4.2 招聘渠道

配置路径：**人才供应云 > 招聘基础服务 > 业务配置 > 通用 > 招聘渠道**。

招聘渠道用于记录候选人来源（线上招聘平台、线下招聘会、内推渠道、猎头合作等）。下游业务（候选人应聘渠道 F7）仅显示使用状态为"可用"的渠道。

新增渠道的关键字段：

| 区块 | 字段 | 必填性/说明 |
|------|------|-------------|
| 基本信息 | 招聘渠道、招聘渠道类型 | 必填；渠道名称重复时报"招聘渠道已存在" |
| 基本信息 | 渠道网址、广告发布方式、支持功能、渠道有效期（日期区间）、注册地址、成立日期、所在城市 | 选填 |
| 适用范围 | 适用行政组织 | **必填**，HR 中台行政组织 F7 多选 |
| 适用范围 | 适用国家、适用 HR 职级方案、适用职级 | 选填 |

渠道操作包括新增、修改、复制、删除、启用/禁用、引入数据/引出数据。渠道暂停使用时**优先使用"禁用"而非删除**，以保留历史数据；渠道详情页含渠道联系人页签（联系人编码与招聘渠道编码不可修改）。

## 4.3 消息模板与常用变量

配置路径：**人才供应云 > 招聘基础服务 > 业务配置 > 通用 > 消息模板**。

消息模板覆盖简历筛选通知、面试通知、笔试通知、录用通知等场景，提前配置模板，发送时直接调用。模板编号规则为 MSTP+6位流水。

模板关键字段：创建组织（招聘管理组织）、控制策略（全局共享/自由分配/私有，默认全局共享）、消息渠道（公共设置-消息渠道中的电子邮件+短信类型，多选必填）、适用招聘类型（社会招聘/内部招聘）、适用场景、邮件主题、邮件附件、邮件正文（富文本+变量）、短信正文（≤200字+变量）。模板数据状态为暂存/已提交/已审核，使用状态为可用/禁用。

适用场景与招聘类型联动：内部招聘支持推荐筛选通知、笔试通知、安排面试通知、修改面试通知、取消面试通知；社会招聘支持**录用通知**。

预置变量（按场景）：

| 场景 | 可用变量 |
|------|----------|
| 录用通知 | 候选人姓名、候选人管理人、管理人电话、管理人邮箱、拟入职公司、报到联系人姓名/电话/邮箱、报到地址、录用通知书失效时间、录用通知书链接 |
| 面试类场景 | 发送日期、面试官姓名、候选人/面试官在线回复、视频面试链接、面试发起人及联系方式、面试地址、应聘职位、候选人姓名、公司、面试时间 |
| 推荐筛选 | 筛选人、推荐人、推荐留言、推荐简历数量、简历筛选链接、推荐日期、推荐人部门 |
| 笔试 | 候选人姓名、应聘职位、公司、行政组织 |

**变量配置规则（实施高频踩坑点）**：

1. 模板中的变量**不能手动键盘输入**，必须从模板编辑区上方蓝色变量列表中选择插入，否则发送时不会解析取值。
2. 若变量列表中没有所需变量，需先在【常用变量列表】中新增：选择取值业务对象与对应字段属性，配置完成后再回模板插入。
3. 选择模板时需先确认【模板常量适用范围】与场景匹配（如笔试通知场景编码为 NOTICE_4）。
4. 变量取不到值的常见根因：业务单据本身未存储该字段数据。解决路径有二：一是将字段扩展到候选人主实体（tsirm_appfile）并在发送前持久化赋值（一对多简化为一对一时推荐）；二是新建关联元数据实体（如"笔试安排"）承载一对多数据，变量从关联实体取值。
5. 每个场景可设置一个默认模板，默认模板会被优先使用。

## 4.4 录用通知书模板（Offer Letter 模板）

配置路径：**人才供应云 > 招聘基础服务 > 业务配置 > 招聘服务直通车 > 录用通知书模板**。

录用通知书模板是直通车专属配置，编号规则为 OFTP+6位流水。可按招聘场景（不同岗位、不同招聘类型）创建多个专属模板，支持修改、删除、设置默认模板（默认模板优先使用）与常用变量配置。

模板字段：创建组织、控制策略、模板名称、适用招聘类型、描述、录用通知书内容（变量+富文本）。预置变量包括：候选人姓名、候选人管理人、管理人电话、管理人邮箱、拟入职公司、拟入职部门、常驻工作地、岗位、职位、职等、职级、试用期、拟入职日期、薪资、试用期薪资、报到联系人姓名/电话/邮箱、报到地址、录用通知书失效时间、录用通知书链接。

**联动参数**：录用通知书有效期、附件加密开关在直通车参数配置 > 录用参数配置中设置（见3.3）；模板匹配规则为按"使用组织 + 基础资料控制策略 + 招聘类型=社会招聘"匹配。

## 4.5 候选人录用登录页配置

| 基本信息 | 编码 / 名称 | 预置 can_offer / 候选人录用 |
| 基本信息 | 用户类型 / 登录场景 | 预置 候选人 / 候选人录用，页面专用于候选人录用场景 |
| 基本信息 | 登录方式 | 预置 短信登录；邮箱登录，应覆盖通知发送渠道（收件人手机号/邮箱），渠道缺失将导致对应候选人无法通过验证 |

## 4.6 隐私声明配置（候选人录用）

候选人录用登录页（见4.5）的"隐私声明"字段即从本处隐私声明数据中选择对应声明。系统预置"招聘服务直通车隐私政策"（编码 **tsrsc_1010_S**，版本 v1.0，作用范围=指定业务对象、业务对象=录用通知书，语种=简体中文），使用状态为可用、数据状态为已审核。

# 6 业务操作要点

## 6.1 招聘职位

路径：**人才供应云 > 招聘服务直通车 > 候选人 > 应聘职位**。

招聘职位是候选人应聘的必要载体，新增候选人时必须选择应聘职位。支持新增、修改、导入招聘职位与修改管理人。第三方招聘系统导入候选人时，应聘职位同步导入/更新至直通车；职位已存在则仅更新不新增。实施时应提前规划职位档案基础数据；对接第三方招聘系统时，同步数据归属判定依赖生态连接配置（见第5章文档链接）。

## 6.2 候选人

路径：**人才供应云 > 招聘服务直通车 > 候选人**。

候选人整合生态导入与手动录入两类来源，应聘状态为未开始/流程中/已结束，支持结束应聘（终止流程）与恢复应聘（重新纳入）。支持新增、批量新增、修改、删除、导入、简历解析、修改管理人。

关键规则：

1. **删除前置条件**：候选人未发生任何录用申请、录用通知、入职协同业务，且应聘状态为"未开始"时才允许删除。
2. **批量新增校验**：候选人姓名为必要信息；未上传原始简历附件不能保存；已上传但解析失败可保存，姓名字段以原始简历文件名填充，超长自动截取。
3. **AI 简历解析**：开启简历解析 AI 参数后，单个/批量新增时简历附件自动解析填充标准简历表单；解析按钮受"简历解析"功能权限控制。
4. **单据互斥校验**：存在流程中的录用申请/录用通知/入职协同时不能新增其他单据；存在历史"审批不通过/已发送/已拒绝/已失效"单据时新增走二次确认弹窗。

## 6.3 录用申请

路径：**人才供应云 > 招聘服务直通车 > 候选人 > 录用**。

录用申请记录候选人录用关键信息（拟入职信息、薪资信息、录用通知书配置），是录用审批与定薪的单据载体。支持新增、修改、删除（仅暂存态）、审批、免审批与薪酬定薪。

拟入职信息关键字段：用工关系类型、用工关系状态、任职类型、任职状态、拟入职公司（由部门自动带出不可编辑）、拟入职部门（权限内行政组织 F7）、常驻工作地、岗位、职位/职等方案/职等/职级方案/职级、职位序列/族/类（职位带出）、试用期（整数+单位）、拟入职日期、其他说明。

录用通知书区块：模板 F7 按"使用组织+基础资料控制策略+招聘类型=社会招聘"匹配；失效时间 = 当前日期 + 参数"录用通知书有效期"（时刻默认 23:59:59 可改）；内容按模板带出可编辑并支持预览。

**定薪控制点**：参数为薪酬定薪时，单据隐藏招聘定薪字段、显示薪酬定薪区域（取薪酬插件）：薪酬管理组织、薪酬结构、定调薪类型、默认币种，分录为定调薪姓名/币种/频率/金额/试用期全额发放/备注；录用申请单与薪酬定薪单同步保存/同步删除/同步废弃；录用通知模板支持薪酬变量替换实际值。

**新增交叉校验矩阵（实施必测）**：

| 校验条件 | 结果 |
|----------|------|
| 应聘状态 = 已结束 | 不允许新增 |
| 存在流程中的入职协同单（暂存/已提交/待重新提交/审批中、发起入职中/发起入职成功、已入职/已转正/已离职） | 不允许新增 |
| 存在流程中的录用申请（暂存/已提交/待重新提交/审批中） | 不允许新增 |
| 存在流程中的录用通知（暂存/已提交/待重新提交/审批中） | 不允许新增 |
| 薪酬定薪方式下未分配"新增候选人定薪单"功能权限 | 不允许新增 |

## 6.4 录用通知与候选人回复

路径：**人才供应云 > 招聘服务直通车 > 候选人 > 通知与回复**。

录用通知单编号规则为 EONT+YYMMDD+6位流水，状态流转为：暂存 → 已提交 → 审批中 → 审批通过/免审批 → 已发送 → 已接受/已拒绝 → 失效（失效不可恢复，可重新创建）。

关键操作与规则：

1. **自动带入**：候选人存在审批通过/免审批的录用申请单时，新增录用通知自动带入模板与失效时间等内容。
2. **报到信息**：报到联系人（平台人员 F7）、电话/邮箱（自动带出可编辑）、报到地址（地址类型为报到地址且可用）。
3. **通知面板**：候选人通知/报到联系人通知开关默认关闭；开启后配置消息模板（场景匹配默认模板）、消息渠道（电子邮件+短信）、收件人、抄送人、邮件主题与正文。添加加密/免密录用通知书按钮按附件加密参数显示。
4. **发送**：生成邮件+短信推送候选人；已发送数据重复发送走二次确认。
5. **候选人回复**：候选人通过登录链接（手机号/邮箱+验证码，登录页取自 HR 基础服务-登录管理-登录页配置，见4.5）选择接受或拒绝；拒绝需二次确认且不可撤销；仅状态为"已发送"时允许回复；未自主回复时招聘专员可代回复。回复后系统给发送人推送"候选人已接受/已拒绝录用"消息。
6. **失效控制**：可设置失效时间（定时任务自动失效）或手工失效（仅免审批/审批通过/已发送/已接受/已拒绝状态）；为候选人创建新录用通知时原通知自动失效；失效后附件不显示、链接不可登录回复。

## 6.5 入职协同申请

路径：**人才供应云 > 招聘服务直通车 > 候选人 > 入职协同**。

入职协同申请是招聘与入职业务衔接的核心单据，记录拟入职公司、部门、岗位等关键信息并上传附件（体检报告、学历验证报告等）。有审批通过/免审批的录用申请时自动带入全部拟入职信息。

入职协同状态全集：暂存、已提交、待重新提交、审批中、审批通过、审批不通过、免审批、已废弃、发起入职中、发起入职成功、发起入职失败、已取消入职、已入职、已转正、已离职。

关键对接规则：

1. **提交校验**：所选用工关系类型+状态下必须有匹配的"变动操作"，否则提示"没有匹配的'变动操作'，请联系入职管理员维护"——核心人力侧变动操作基础资料需提前维护。
2. **发起入职**：仅状态为审批通过/免审批/发起入职失败时可发起；成功后核心人力"待启动入职"新增记录（基本信息取中台拟入职人员表，人事管理组织、用工关系、任职信息、试用期、部门/岗位/职位/常驻工作地取协同单，来源信息取候选人的招聘类型与渠道，offer 编号取关联录用申请单编号）。
3. **取消入职**：仅状态为发起入职成功时可取消；弹窗必填终止类型（基础资料），选填终止原因与说明；未启动的待启动入职数据删除，入职流程中的转"入职终止"；取消后可再次新增协同单发起入职。
4. **人事变动状态回传**：新员工完成入职/转正/离职手续后，状态自动同步回招聘端并回传第三方招聘系统。

## 6.6 工作台

路径：**人才供应云 > 招聘服务直通车 > 工作台**（需具备直通车功能权限）。

工作台由四个区域构成：快速发起（社招候选人、校招候选人、外部人才、外部人才库入口，支持自定义添加）、候选人区域统计（待重新提交/审批通过/已发送/已入职/发起入职失败热区，点击跳转对应列表）、录用与入职协同流程区域（按节点快速进入候选人列表、核心人力入职办理列表或第三方招聘系统登录页）、数据统计区域（漏斗图展示应聘、录用、入职各环节数据，仅包含直通车范围内数据，默认按社招、上月过滤）。

# 7 工作流与审批配置

录用申请单、录用通知单、入职协同申请单三类单据提交时均需匹配审批工作流，否则提示"未匹配到工作流，请联系管理员配置"。

**预置工作流模板（建议引用）**：系统在**工作流服务 > 流程模板列表**预置了直通车三个审批流程模板，实施时建议直接引用预置模板后再按企业审批制度调整审批人规则，提高配置效率：

| 模板编码 | 模板名称 | 单据 | 单据标识 | 是否预置 |
|----------|----------|------|----------|----------|
| PROCTPL_TSCSC_EA | 录用申请审批流程 | 录用申请单 | tsrsc_offer | 是 |
| PROCTPL_TSCSC_EN | 录用通知审批流程 | 录用通知单 | tsrsc_offernotice | 是 |
| PROCTPL_TSCSC_OCA | 入职协同单申请审批流程 | 入职协同申请单 | tsrsc_induction | 是 |

实施要点：

1. **审批流配置**：优先引用上述预置工作流模板为三类单据配置审批流；支持按不同人群自动匹配录用审批流程。
2. **免审批**：可通过"提交并生效"实现免审批，是否允许由单据"提交/提交并生效"权限分配控制。
3. **指定审批人**：需三处同时打开——工作流单据提交节点开关、工作流配置开关、公共设置的工作流指定审批人配置；开启后提交时弹出选人界面。
4. **驳回与废弃**：审批驳回后单据变为待重新提交，仅待重新提交状态可废弃；仅已提交状态可撤销回暂存；二级审批人不同意则申请终止。
5. **审批可见内容**：审批人可见的候选人信息由直通车参数控制（见3.3、3.4），实施时按信息最小化原则配置。

# 8 权限与安全

## 8.1 数据权限模型

候选人数据权限由三层判定构成：招聘管理组织归属判定（对接第三方招聘系统时基于生态连接配置，见第5章）+ 所属行政组织 + 单据预置"管理人"字段按人管控。消息模板、录用通知书模板、生态租户均基于招聘管理组织做横向越权校验。

## 8.2 安全能力清单

| 能力 | 说明 |
|------|------|
| 录用通知书安全访问 | 手机/邮箱验证码登录、链接有效期管控、失效后不可访问 |

1. 直通车参数配置已按招聘管理组织完成初始化，作用域选择正确。
2. 定薪方式参数与客户方案一致；薪酬定薪场景下薪酬功能已订阅部署、"新增候选人定薪单"权限已分配。
3. 录用通知书有效期、附件加密参数按客户要求设置，录用通知书失效时间推算正确。
4. 简历解析 AI 参数开启前已确认 AI 大模型订阅部署就绪，解析结果正确填充标准简历。
5. 三类单据审批可见内容参数按信息最小化原则配置。

## B. 基础数据

1. 招聘渠道：必填项（渠道、类型、适用行政组织）完整，可用性状态正确，候选人应聘渠道 F7 仅显示可用渠道。
2. 消息模板：录用通知等场景模板已审核可用，默认模板已设置，变量均从变量列表插入且取值正确。
3. 录用通知书模板：按场景配置完成，默认模板已设置，预置变量（含定薪变量）替换正确。
4. 候选人录用登录页：预置 can_offer 页面核对无误，短信/邮箱登录可用，隐私声明与勾选确认联动正确，移动端/PC 端模板已按客户品牌个性化。

## C. 第三方招聘系统集成（如适用）

1. 直通车与第三方招聘系统的集成配置已按第5章链接文档完成，接口联调通过，相关调度任务已启用。
2. 候选人同步：从第三方招聘系统导入候选人成功，简历与附表信息同步完整；候选人数据归属（招聘管理组织、所属行政组织、管理人）符合配置。
3. 状态回传：入职、转正、离职、取消入职状态正确回传第三方招聘系统。

## D. 工作流与权限

1. 引用预置工作流模板后三类单据审批流匹配正确、审批链路顺畅；无工作流时提示语出现，配置后流程顺畅。
2. 免审批（提交并生效）、驳回重提、废弃、撤销路径验证通过。
3. 角色功能权限、单据权限、热区跳转权限、数据权限（招聘管理组织维度）按分配方案验证。
4. 指定审批人场景（如启用）三处开关均已打开且选人弹窗正常。

## E. 端到端业务验证

1. 完整流程：第三方招聘系统候选人导入 → 录用申请（含定薪）→ 录用审批 → 录用通知发送（邮件+短信）→ 候选人安全登录回复接受 → 入职协同 → 发起入职 → 核心人力待启动入职生成 → 入职办理 → 状态回传第三方招聘系统"已入职"。
2. 拒绝场景：候选人拒绝录用，发送人收到消息，单据状态正确。
3. 失效场景：通知书超期由定时任务自动失效；手工失效后链接不可回复。
4. 取消入职场景：发起入职成功后取消，待启动入职删除或转入职终止；可再次新增协同单发起入职。
5. 转正/离职场景：状态回传直通车并回传第三方招聘系统（已转正/已离职）。
6. 轻量化流程（如启用）：无需录用申请/录用通知，候选人直接发起入职协同链路验证通过。
7. 交叉校验：流程中单据互斥、应聘状态已结束拦截、历史单据二次确认弹窗均符合预期。

## F. 安全与合规

1. 录用通知书加密附件需密码查看；链接有效期到期后不可访问。
2. 候选人登录验证（手机号/邮箱）正常；非发送手机号被拦截。
3. 定薪数据权限：无定薪查询权限时薪酬信息不展示。
4. 隐私声明：预置"招聘服务直通车隐私政策"（tsrsc_1010_S）可用且已审核，登录页关联正确、勾选同意联动正常；签署与匿名化规则（如启用）验证。

## G. 收尾

1. 定时任务（tsrsc_OfferLetterInvld、AtsMsgTask）运行状态巡检正常。
2. 工作台统计与漏斗数据口径确认（仅直通车范围、默认社招过滤）。
3. 关键用户培训完成：招聘专员、薪酬专员、HRSSC、IT 管理员分别掌握对应操作。
4. 上线演练问题清零，验收记录归档。

# 11 常见问题与实施风险

**Q1：候选人同步失败，如何排查？**

Moka端提示“导入成功”只代表消息已发出，金蝶侧仍需经调度任务消费、调用Moka接口取数、保存候选人实体等多个环节。请按以下顺序定位：

1. **集成资源未启用/未发布**：参照第5章集成文档，检查WebAPI、苍穹微服务、服务流程是否已启用/发布；新导入或升级后的资源默认禁用。
2. **AtsMsgTask调度任务未启用**：该任务负责消费Moka消息，路径见第9章；未启用则消息一直停留在队列。
3. **生态租户或组织映射错误**：检查生态租户、生态组织与招聘管理组织/行政组织的映射，错误时数据可能写入不可见的组织或被丢弃。
4. **候选人应聘ID问题**：Moka标准集成要求应聘ID为纯数字，且需在Moka中存在；候选人日志中通常会有明确校验提示。
5. **二开必填字段导致保存失败（隐藏失败）**：客户在候选人实体`tsrsc_appfile`/`tsrsc_appfilesocial`或附表上新增必填字段，但Moka同步未给该字段赋值，保存时校验不通过导致整单回滚。日志中可见`EntityOperateService.execute(..., save)`返回`successIds = null`，并伴随`Msg数据校验发现错误`。解决方案是取消必填属性，或在前置处理服务流程`tsrsc_moka_application_before_pre`中为该字段赋默认值/补充映射。

详细排查方法可参考：[Moka推送候选人显示成功但金蝶未生成候选人](../faq/faq-moka-candidate-sync-hidden-failure.md)。

**Q2：消息模板变量取不到值？**

依次检查：变量是否从蓝色变量列表插入（手动键入不解析）；模板常量适用范围与场景是否匹配；取值业务对象是否配置正确；业务单据是否已持久化存储该字段数据（发送前需先写入）。一对多数据需新建关联实体承载。

**Q3：入职协同提交报"没有匹配的'变动操作'"？**

所选用工关系类型+状态在核心人力侧缺少对应变动操作基础资料，需联系入职管理员在核心人力基础资料中维护变动操作后重新提交。

**Q4：候选人无法打开或回复录用通知书链接？**

检查通知书是否已失效（超过有效期由定时任务自动失效，或已被手工失效/被新通知替代失效）；登录手机号须为发送时的候选人手机号，否则报"非有效的手机号码"；仅状态为"已发送"的通知书允许回复。

**Q5：客户希望不同人群使用不同定薪方式？**

定薪方式为全局参数二选一（招聘定薪/薪酬定薪）。按单据字段动态切换属于二开场景，需通过表单插件实现并评估旧定薪方式残留数据清理，建议在方案阶段明确并走二开流程。

**Q6：调度中心看不到"人才供应云"分类？**

权限问题：用 admin 账号在 基础服务云 > 安全管理 > 权限管理 > 管理员 选中"HR管理员分组"做分组授权，授予"人才供应"应用范围权限后刷新。

**Q7：与第三方招聘系统的集成接口不通？**

参照第5章集成文档链接核对资源部署与启用状态：新导入的集成资源（WebAPI、微服务、服务流程）默认禁用，需手工启用/发布；同时检查数据源系统连接配置是否正确、调度任务是否已启用。

**风险提示**：

1. 录用通知拒绝、失效操作不可恢复，演练环境操作需谨慎，正式数据建议先在测试环境完整演练。
2. 薪酬定薪方式下录用申请单与薪酬定薪单同步保存/删除/废弃，误删操作会联动影响薪酬数据。
3. 集成资源（WebAPI、微服务、服务流程）升级或重新部署后可能回到禁用状态，升级后需复检。
4. AI 大模型、薪酬功能为订阅依赖，未订阅而开启对应参数会导致功能不可用，实施启动时应提前确认许可。
5. 候选人同步覆盖更新不改变招聘管理组织、所属行政组织与管理人，组织映射调整不会影响存量数据归属，需在上线前一次性确认映射方案。
